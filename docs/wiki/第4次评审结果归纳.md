## 一、需求逐条归纳

### 1.1 B.1 订单升级

| 编号 | 需求原文 | 实现要点 | 证据 | 结论 |
| --- | --- | --- | --- | --- |
| B.1-1 | 订单包括客户下单、商家确认、备货完成、开始发货、交易完成 5 个状态 | `OrderStatus` 五状态 + `CANCELED` 终态；卖家按序推进，跨状态被拒绝 | `entity/enums/OrderStatus.java`；`POST /api/seller/orders/{id}/confirm|prepare|ship|complete` | 满足 |
| B.1-2 | 开始发货状态前，客户可以取消订单 | 仅 `PLACED / CONFIRMED / PREPARED` 可取消 | `POST /api/customer/orders/{id}/cancel`；`OrderStatus#cancellableByCustomer()` | 满足 |

| `CANCELED` | 终态，记录取消方与原因，库存回滚 | 无 |

## 三、验证证据

### 3.1 接口实测

| 场景 | 操作 | 实测结果 |
| --- | --- | --- |
| 多件合并下单 | 购物车勾选 2 件 → checkout | 生成 1 个订单，`itemCount=2`，金额等于明细之和 |
| 状态推进 | 依次 confirm → prepare → ship → complete | 状态逐级变化，节点时间写入 |
| 客户端取消 | `PREPARED` 状态调用客户取消 | 成功，`canceledBy=CUSTOMER`，库存逐项回滚 |
| 发货后取消 | `SHIPPED` 状态调用客户取消 | 被拒绝，提示「订单已开始发货，无法取消」 |
| 完成前商家取消 | `COMPLETED` 前调用商家取消 | 成功并记录原因 |
| 完成后商家取消 | `COMPLETED` 调用商家取消 | 被拒绝 |
| 重复取消 | 已取消订单再次取消 | 被拒绝「订单已取消，无需重复操作」 |
| 批量转收藏 | 勾选多件 → to-favorites | 返回转移件数，购物车对应项移除 |

### 4.2 镜像方案

仓库根目录 `Dockerfile` 采用**方案 A：单镜像**——前端 `dist` 并入后端 jar 的 `static` 目录，由 Spring Boot 统一托管，一个容器同时提供页面与 API，均监听 8080。

三阶段构建：

| 阶段 | 基础镜像 | 作用 |
| --- | --- | --- |
| frontend | `node:22-alpine` | `npm ci` + `npm run build`，使用 npmmirror 镜像源 |
| backend | `maven:3.9-eclipse-temurin-17` | 并入 `dist` 后 `mvn package`，使用阿里云 Maven 镜像 |
| runtime | `eclipse-temurin:17-jre` | 仅拷贝可执行 jar，`ENTRYPOINT java -jar app.jar` |

`.dockerignore` 已排除 `.git`、`node_modules`、`dist`、`target`、`uploads`、`docs`、`*.log`。

## 七、归纳结论

1. **挑战 B 七条需求全部落地**，每条都有接口与页面支撑，可逐条复现验证。
2. **规则边界可验证**：发货后客户取消、完成后商家取消、重复取消三类越权操作均被拒绝。
3. **数据一致性成立**：多件合并下单为单事务，明细为价格快照，取消后库存逐项回滚，销量只在交易完成时累加。
4. **构建与部署可复现**：后端打包、前端构建、Docker 镜像构建三项均通过，镜像 `pingxixi:0.4.0` 启动后前后端同端口可用。
5. **对既有能力无破坏**：在 v0.3.0 基础上增量合入，挑战 A 与基线意向流程回归通过。

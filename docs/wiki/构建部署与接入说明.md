# 构建部署与接入说明

本说明对应课程「系统验收标准」中的**构建**与**部署**两个维度，给出环境要求、构建步骤、运行方式与接入约定。本版本为 v0.1.0（第 1 次阶段性评审，2026-10-08）。

---

## 一、环境要求

| 组件 | 要求版本 | 本机实测版本 | 用途 |
| --- | --- | --- | --- |
| JDK | 17 及以上 | 21.0.10 LTS | 编译与运行后端 |
| Maven | 3.8 及以上 | 3.9.16 | 构建后端 |
| Node.js | 18 及以上 | 22.17.1 | 构建与运行前端 |
| npm | 9 及以上 | 10.9.2 | 安装前端依赖 |
| 数据库 | 无需额外安装 | — | 默认使用内置 H2 内存数据库 |

操作系统：Windows / macOS / Linux 均可，本文以 Windows 为例。

## 四、构建步骤

### 4.1 构建后端

```bash
cd backend
mvn clean package -DskipTests
```

构建产物：`backend/target/mall-backend-0.0.1-SNAPSHOT.jar`

构建工具说明：Maven 通过 `backend/pom.xml` 声明依赖与插件；首次构建需联网下载依赖，约 1~3 分钟。

### 4.2 构建前端

```bash
cd frontend
npm install          # 首次执行，或依赖变更后执行
npm run build
```

构建产物：`frontend/dist/`（静态文件，可交由任意静态服务器托管）

### 4.3 获取源码包

- 版本包（含全部源码与文档）：`https://github.com/kaskk345/pingxixi-online-shoppingplatform/releases/tag/v0.1.0`
- 或从仓库首页 **Code → Download ZIP** 下载

## 五、运行方式

### 5.1 一键启动（推荐，评审现场使用）

双击仓库根目录的 **`启动pingxixi.bat`**：脚本会依次启动后端与前端，并自动打开浏览器。

### 5.2 分步启动（开发调试）

```bash
# 终端 1：后端（先在后台起来）
cd backend
mvn spring-boot:run            # 默认 http://localhost:8080

# 终端 2：前端
cd frontend
npm run dev                    # 默认 http://localhost:5173
```

访问入口：

| 入口 | 地址 |
| --- | --- |
| 买家端首页 | http://localhost:5173 |
| 卖家后台登录 | http://localhost:5173/login |
| 买家凭口令码查询 | http://localhost:5173/track |
| 后端接口根 | http://localhost:8080/api |
| H2 数据库控制台 | http://localhost:8080/h2-console |

默认卖家账号：`admin` / `admin123`（首次启动由 `DataInitializer` 自动创建，密码以 BCrypt 存储）。

### 5.3 前后端如何连通

前端所有请求以 `/api` 为前缀，由 Vite 开发代理转发到后端：

```js
// frontend/vite.config.js
proxy: {
  '/api': 'http://localhost:8080',
  '/uploads': 'http://localhost:8080'
}
```

因此**开发模式下必须同时启动前后端**；只启动前端会出现数据为空、请求失败。

## 六、配置说明

`backend/src/main/resources/application.yml`：

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `server.port` | 8080 | 后端端口 |
| `spring.datasource.url` | `jdbc:h2:mem:mall;DB_CLOSE_DELAY=-1;MODE=MySQL` | 默认内置内存库 |
| `spring.jpa.hibernate.ddl-auto` | `create` | 启动时重建表结构 |
| `spring.h2.console.enabled` | true | 开启 H2 控制台，路径 `/h2-console` |
| `mall.upload-dir` | `uploads` | 商品图片上传目录，**相对于后端工作目录** |

> 注意：内存数据库重启即重置，启动时会重新写入默认卖家账号与示例商品。这是刻意设计，避免评审现场依赖外部数据库。

### 切换到 MySQL（可选，持久化）

1. 取消 `backend/pom.xml` 中 `mysql-connector-j` 依赖的注释；
2. 修改 `application.yml` 的 `spring.datasource`：

```yaml
url: jdbc:mysql://localhost:3306/mall?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai
driver-class-name: com.mysql.cj.jdbc.Driver
username: root
password: 你的密码
```

3. 将 `ddl-auto` 改为 `update`，并先手动执行 `CREATE DATABASE mall;`。

## 七、接口清单（与当前实现一致）

### 买家端（免登录）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/products/on-sale` | 当前唯一可购买商品（无则 data 为 null） |
| GET | `/api/products/{id}` | 商品详情 |
| POST | `/api/intents` | 提交购买意向，返回口令码 |
| GET | `/api/intents/track?code=xxx` | 凭口令码查询排队位次与状态 |
| PUT | `/api/intents/track` | 凭口令码修改姓名、电话 |
| POST | `/api/intents/cancel` | 凭口令码撤销意向 |

### 卖家端（需 `X-Token` 请求头）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/seller/login` | 登录，返回 token |
| PUT | `/api/seller/password` | 修改密码 |
| GET | `/api/seller/products` | 全部商品（含历史） |
| POST | `/api/seller/products` | 发布商品（已有可购买商品时拒绝） |
| POST | `/api/seller/products/{id}/freeze` | 手动冻结 |
| POST | `/api/seller/products/{id}/unfreeze` | 解冻，恢复在售 |
| POST | `/api/seller/products/{id}/off-shelf` | 手动下架 |
| POST | `/api/seller/upload` | 上传商品图片 |
| GET | `/api/seller/intents` | 意向列表（不返回口令码） |
| POST | `/api/seller/intents/{id}/start` | 与队首开始交易（商品自动冻结） |
| POST | `/api/seller/intents/{id}/succeed` | 登记交易成功（商品下架） |
| POST | `/api/seller/intents/{id}/fail` | 登记交易失败（商品恢复在售） |
| POST | `/api/seller/intents/{id}/void` | 失败意向作废 |
| POST | `/api/seller/intents/{id}/requeue` | 失败意向重新排队（位次到队尾） |

### 统一返回格式

```json
{ "code": 0, "message": "success", "data": { } }
```

- `code = 0` 表示成功；业务错误返回 `code != 0` 并在 `message` 给出提示；
- 未登录访问卖家接口返回 **HTTP 401** 与 `code = 401`。

## 八、部署方式

### 8.1 开发/演示部署（当前采用）

后端以 `mvn spring-boot:run` 或 `java -jar target/mall-backend-0.0.1-SNAPSHOT.jar` 运行（JVM 内嵌 Tomcat，无需额外 Web 容器）；前端以 Vite 开发服务器运行。

### 8.2 单机生产式部署（前端静态文件由后端托管）

```bash
cd frontend
npm run build                        # 生成 frontend/dist
# 将 dist 内容复制到后端静态目录
backend/src/main/resources/static/
cd ../backend
mvn clean package
java -jar target/mall-backend-0.0.1-SNAPSHOT.jar
```

之后仅访问 `http://localhost:8080` 即可，无需 5173 端口。

> 注意：前端路由使用 history 模式，若采用此方式，需在后端补充「找不到的路径返回 index.html」的转发配置，否则刷新 `/seller/products` 等地址会 404。

## 九、常见问题

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 前端页面能开但列表空白 | 只启动了前端 | 同时启动后端（8080） |
| 后端启动报端口占用 | 8080 已被占用 | 结束占用进程，或修改 `server.port` 并同步修改 `vite.config.js` 代理地址 |
| 首次启动很慢 | Maven 下载依赖 | 等待 1~3 分钟，属正常 |
| 重启后数据没了 | H2 为内存数据库且 `ddl-auto=create` | 属预期行为；需持久化请切换 MySQL |
| 上传的图片访问 404 | 上传目录相对后端工作目录 | 必须在 `backend` 目录下启动后端 |
| `mvn` 或 `npm` 不是内部命令 | 环境变量未配置 | 安装并配置 JDK / Maven / Node 的 PATH |

## 十、部署自检

部署完成后，在仓库根目录执行接口自检脚本，确认后端各项规则可用：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\verify-api.ps1
```

脚本会自动走完「登录 → 查看在售商品 → 提交意向 → 排队 → 冻结 → 登记成交」全流程并输出通过/失败统计（最新实测：14 项全部通过，详见《测试用例与运行说明》）。

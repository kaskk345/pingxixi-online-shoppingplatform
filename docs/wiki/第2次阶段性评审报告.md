| 编号 | 升级点 | Sprint 1 基线 | 升级后实现 | 验证证据 |

## 三、Sprint 1 基线复测（重点一）

### 3.1 接口实例测试（命令行复测）

- 命令：`scripts/verify-api.ps1`（单品单卖交易闭环自检）
- 环境：后端 `:8080` 启动就绪后运行；**执行于 2026-10-21，即 A.1/A.2 升级之前**，结论对应 Sprint 1 基线
- 结果：**14 项断言全部通过，0 失败**（对应用例 TC-01 ~ TC-13）
- 覆盖链路：未登录拒访(401) → 登录取 token → 读取在售 → 单品单卖约束 → 提交 3 条意向排队 → 非队首禁交易 → 队首交易自动冻结 → 冻结期拒新意向 → 成交下架 → 其余意向离队 → 口令码失效 → 卖家侧不泄露口令码
- 结论：Sprint 1 核心业务规则在运行态可完整复现；升级后该脚本需按 2.6 同步为多商品版。

## 六、遗留问题与风险

以下为当前范围内的待办项，均不影响基线闭环与 A.1/A.2 的主要功能验收，后续是否纳入下一迭代以实际排期为准。

| 类别 | 现状 | 影响 |
| --- | --- | --- |
| 买家端历史商品浏览页（前端） | 后端已对下架商品归档并挂意向流水（只读、买家不可见），卖家后台可看全部商品，但买家端历史浏览页未实现 | 买家侧无历史查看入口 |
| 基线自检脚本版本 | `scripts/verify-api.ps1` 仍按「唯一在售」编写（TC-03/TC-04），升级后该断言语义已失效 | 需产出多商品版自检脚本，否则无法用一条命令回归升级后全链路 |
| 数据统计看板（前端） | 后端接口 `GET /api/seller/stats` 已提供，前端页面未接入 | 卖家侧无可视化统计 |
| 意向终态命名口径 | 状态机终态命名为 `VOID`，与需求文档「失败」表述存在口径差异 | 不影响主流程，文档/接口需统一 |
| 并发压力测试 | 同商品并发提交 / 并发扣库存未做压测 | 高并发正确性（尤其库存扣减）未经量化验证 |
| 运行录屏 | 课程要求的操作录屏未制作（界面截图已补充 12 张作为替代证据） | 演示材料完整性缺口 |

## 七、评审结论

1. **基线与升级均通过**：Sprint 1「单品单卖」交易闭环在 2026-10-21 运行态复测中完全通过（接口 14 项断言 + 5 个界面验证），八项目标按当时定义 100% 达成，可认定为 Sprint 1 正式收尾。
2. **A.1 / A.2 挑战升级已落地**：2026-10-22 完成实现（提交 `4f2fde7`，31 文件 / +1148 行），12 项升级用例与 7 张升级后界面截图全部通过，商品侧（多商品、二级分类、库存与自动下架、浏览 + 搜索、多图富媒体）与客户侧（自由注册、历史下单、商家客户视图）要求逐条对应、可验证。
3. **遗留项均为增强型需求**，其中「基线自检脚本多商品化」为下一迭代需优先补齐的工程项，其余按需排期。

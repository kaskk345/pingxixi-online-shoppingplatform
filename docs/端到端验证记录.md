# 端到端验证记录

> 记录单品单卖改造完成后，对主流程与关键规则约束的实测结果。
> 验证方式：本地启动后端（:8080）与前端（:5173），通过 HTTP 接口逐条验证。
> 验证日期：2026-10-07

## 一、主流程

| # | 步骤 | 实测结果 |
| --- | --- | --- |
| 1 | 卖家发布商品 | 商品直接为「在售」，库存 1 |
| 2 | 买家提交购买意向（姓名 + 电话） | 返回唯一口令码，状态「等候中」 |
| 3 | 连续提交三条意向 | 各得唯一口令码，排队位次分别为第 1 / 2 / 3 位 |
| 4 | 卖家与队首开始交易 | 商品自动转为「已冻结」，意向转为「交易中」 |
| 5 | 线下交易后登记成功 | 商品转为「已下架」，其余等候意向置为「已作废」 |
| 6 | 登记交易失败 | 商品转为「已恢复在售」，等候队列继续有效 |

## 二、规则约束验证

| # | 验证点 | 期望 | 实测 |
| --- | --- | --- | --- |
| 1 | 先到先得 | 只能与队首开始交易 | 对非队首操作被拒绝，提示「请先到先得」 |
| 2 | 自动冻结 | 进入交易时商品冻结 | 通过，商品状态 FROZEN |
| 3 | 冻结期保护 | 冻结期间不接受新意向 | 通过，提示「商品交易中，暂不接受新的购买意向」 |
| 4 | 单品单卖 | 已有可购买商品时禁止发布 | 通过，提示需先完成交易或手动下架 |
| 5 | 交易成功 | 商品直接下架，不用先解冻 | 通过，商品 OFF_SHELF |
| 6 | 交易失败 | 商品恢复在售 | 通过，商品 RESTORED |
| 7 | 重新排队 | 沿用原口令码，位次重置到队尾 | 通过，新记录沿用原码且排到队尾 |
| 8 | 口令码生命周期 | 交易结束或下架后失效 | 通过，下架后查询/修改/撤销均被拒绝 |
| 9 | 卖家侧信息 | 不返回口令码 | 通过，列表接口 code 字段为空 |

## 三、典型输出示例

```
提交三条意向 → 口令码 34MAZYK2 / WP9MC3SS / 6DYDMCDG
排队位次      → 第 1 位（前 0 人）/ 第 2 位（前 1 人）/ 第 3 位（前 2 人）
跳队拦截      → "请先到先得：只能与排在最前面的意向人交易"
冻结期提交    → "商品交易中，暂不接受新的购买意向"
重新排队      → 新记录沿用原码 AGM3EYPP，位次重置为第 2 位
交易成功      → 商品 OFF_SHELF，其余等候意向 VOID
口令码失效    → "商品已下架，该口令码已失效"
```
